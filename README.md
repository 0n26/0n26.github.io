# 0n26 / portfolio

Готовый статический сайт для GitHub Pages. React + Vite, локальные SVG, без CDN, сторонних шрифтов, аналитики и runtime-запросов к API. Графит, слоновая кость и светло-голубой акцент продолжают дизайн профильного набора 0n26.

## Быстрый запуск

Нужен Node.js 24 LTS (минимум 24.15) и npm.

```sh
npm ci
npm run dev
```

Открыть адрес из терминала. Продакшен-проверка:

```sh
npm test
npm run build
npm run test:dom
npm run preview
```

Результат сборки в `dist/`. Для локального просмотра нужен HTTP-сервер: не открывайте `index.html` двойным кликом через `file://`.

## GitHub Pages

Рекомендуемый репозиторий: **0n26/0n26.github.io**, адрес сайта: **https://0n26.github.io/**. Это отдельный репозиторий, не профильный **0n26/0n26**, в котором живёт README профиля.

1. Создайте репозиторий `0n26.github.io` в аккаунте 0n26. Для бесплатного Pages используйте публичный репозиторий.
2. Загрузите содержимое этой папки в корень ветки `main`, включая скрытую папку `.github`, `package.json` и `package-lock.json`. Не загружайте `node_modules`.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Запустите **Actions → Deploy portfolio to GitHub Pages → Run workflow**, либо сделайте push в `main`.
5. После успешного deployment GitHub покажет адрес в окружении `github-pages` и в Settings → Pages.

Workflow уже включён: установка по lockfile, unit-тесты, сборка и официальный Pages artifact/deploy. Deploy job имеет только `pages: write` и `id-token: write`; чтение исходников ограничено `contents: read`. Секреты вручную добавлять не нужно. Архив подготовлен локально: репозиторий и сайт автоматически не создавались.

### Если имя репозитория другое

Например, репозиторий `0n26/portfolio` публикуется на `https://0n26.github.io/portfolio/`. Workflow берёт путь из `configure-pages`, а локальная сборка умеет определять его по `GITHUB_REPOSITORY`. Внешние GitHub-ссылки остаются абсолютными и не получают префикс.

Для локальной проверки подпути в bash:

```sh
BASE_PATH=/portfolio/ npm run build
npm run preview
# Откройте http://localhost:4173/portfolio/
```

В PowerShell: `$env:BASE_PATH='/portfolio/'; npm run build`. Для обычной корневой сборки удалите переменную или установите `/`. При пользовательском домене настройте его в Pages; `configure-pages` передаст корректный путь. Не добавляйте чужой домен в `CNAME`.

Одностраничная навигация использует якоря (`#projects`, `#stack`), поэтому не требует SPA-перенаправлений или файла `404.html`.

## Что редактировать

- `src/data.js` — описание профиля, все проекты, категории, теги и стек.
- `src/styles.css` — токены, компоненты, адаптивность.
- `src/main.jsx` — семантическая структура и фильтрация.
- `public/assets/` — фирменный знак, орбита, обложки и оригинальные карточки.
- **[DESING.md](DESING.md)** — обязательная дизайн-система. Имя файла сохранено именно в запрошенном написании.
- `SOURCES.md` — источники описаний и технические документы.

Чтобы добавить проект, добавьте объект в `projects` с уникальным `id` и SVG-обложку в `public/assets`. Фильтры и счётчики обновятся автоматически. Новую категорию нужно добавить в `filters`. Не путайте число карточек с рейтингами или статистикой GitHub.

## Проверки

`npm test` проверяет пути Pages, данные, фильтрацию, доступность ассетов и атрибуцию k2-port. `npm run test:dom` после сборки проверяет реальный production bundle в jsdom (рендер React, фильтры, состояния кнопок, счётчики и URL ассетов). Это не визуальная проверка. Фактический отчёт: [QA.md](QA.md). Browser-тест требует установленный Chromium:

```sh
npm run build
npm run preview
# В другом терминале:
npm run test:browser
```

По умолчанию Chromium находится по `/usr/bin/chromium`. На другой ОС задайте `CHROMIUM_PATH` (путь к Chrome/Chromium). Для подпути задайте `TEST_URL=http://localhost:4173/portfolio/`. Тест проверяет фильтр, skip-link, изображения, переполнение на 320/390/768/1440 px, reduced motion и ошибки браузера; скриншоты сохраняются в `test-results/`. CI не запускает browser-тест, поэтому системный Chromium для Pages-сборки не нужен.

Сайт не требует серверной части. Не помещайте ключи API или другие секреты в клиентский код: весь опубликованный проект доступен посетителю.

## Ассеты и права

Фирменные SVG продолжают предоставленную визуальную систему 0n26. В архив не включены игровые ассеты Krastorio 2; ссылка на мод сохраняет атрибуцию оригинальных материалов. Публикационная лицензия на ваш бренд или проекты этим шаблоном не назначается. Зависимости имеют собственные лицензии.

## Мини-робот 0n26

В сайт уже встроен маленький пиксельный CRT-робот в фирменной палитре: графит, слоновая кость, ледяной голубой. На экране его ник `0n26`; он моргает, радуется, удивляется, интересуется, отдыхает, гуляет и машет рукой. Нажмите на робота для смены эмоции. Карточки и фильтры проектов вызывают любопытство.

У робота постоянно доступны пауза и скрытие; после скрытия остаётся кнопка возвращения. Наведение и клавиатурный фокус останавливают автономную анимацию. Системная настройка reduced motion отключает её полностью. На телефоне персонаж компактнее, кнопки сохраняют область касания 44 px.

- Компонент: `src/Mascot.jsx`; стили: `src/mascot.css`.
- Готовые прозрачные SVG и PNG всех восьми состояний: `public/assets/mascot/`.
- Лист эмоций: `public/assets/mascot/emotions-preview.png`.
- Проверка поведения и очистки ресурсов: `npm run test:mascot`.
- Визуальные спецификации и триггеры: раздел «Мини-робот» в `DESING.md`.

Робот полностью локальный, без чата, трекинга и внешнего API. Пауза и скрытие сохраняются только в текущем сеансе страницы. Исходный SVG-набор можно использовать отдельно от React.

Для редактирования исходной геометрии используйте `scripts/generate-mascot.py`. Повторная генерация SVG/PNG/листа эмоций требует Python с CairoSVG и Pillow; для запуска сайта Python не нужен, все готовые ассеты уже включены.
