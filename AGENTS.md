# Инструкции агентам

## С чего начать

- Прочитать [правила участия](CONTRIBUTING.md). Они одинаковы для людей и агентов.
- Node из `.nvmrc`, `npm ci`, `npm run dev`. Перед PR: `npm run check` (типы, тесты, production-сборка). Изменения UI проверить в браузере; `npm run preview` нужен для проверки production PWA.
- Работать в ветке от `main`, открыть PR с Conventional Commit в заголовке. Не пушить напрямую в `main`, не делать merge/approve, не менять защиту ветки и не выпускать релиз вручную. Merge выполняет сопровождающий.

## Границы модулей

- `src/app/` — оболочка и hash-маршруты для статического GitHub Pages; не добавлять сервер или правила rewrite.
- `src/pages/` — экраны с точкой входа `index.ts`; `src/components/` — самостоятельные React-компоненты. Компоненты не импортируют страницы.
- `src/catalog/` — общий каталог и сопоставление тайтлов без React. Общие функции для URL находятся в `src/routes/`.
- `src/sources/` — API-адаптеры с отдельными папками и точками входа `index.ts`. Нормализовать внешние данные и HTTPS-ссылки до передачи в UI. Новый источник регистрируется в `src/sources/index.ts`; плеер не меняется.
- `src/components/player/` — HLS и опциональный Anime4K. Не импортировать API-адаптеры сюда. Воспроизведение без WebGPU — обязательный сценарий.
- `src/pages/changelog/` — отображение корневого `changelog.md` из артефакта сборки. Версия из `package.json`, не дублировать её вручную.
- `tests/` — все тесты, включая тесты скриптов; не размещать тестовые файлы в `src/`.

Клиент видит любые переменные сборки и URL. Не добавлять секреты, приватные ключи, прокси, обход CORS или геоограничений. Не кэшировать плейлисты, видеосегменты или ответы сторонних API в service worker.
