# Работа с ИИ в этом репозитории

Запускайте CLI из корня репозитория. [AGENTS.md](../AGENTS.md) — единственная общая точка входа для агентов: в ней границы архитектуры и ссылки на документы. Если инструмент не подхватил файл автоматически, начните задачу с «Прочитай `AGENTS.md` в корне и следуй его ссылкам».

## Где хранить контекст

| Что | Где хранить |
| --- | --- |
| Обязательные границы слоёв и ограничения для агента | `AGENTS.md`, короткими проверяемыми правилами. |
| Как устроен проект и как подключить источник | [README.md](../README.md). |
| Ветки, PR, проверки и релизы | [CONTRIBUTING.md](../CONTRIBUTING.md). |
| Тема, токены и оформление интерфейса | [desing.md](../desing.md). |
| Личные предпочтения, модель, параметры CLI и приватные заметки | Пользовательские настройки CLI вне репозитория. Токены и ключи — только в хранилище секретов, не в Markdown. |
| Текущая задача, критерии приёмки и результаты проверки | Issue или PR; не переносить историю чата и временные планы в `AGENTS.md`. |

Обновляйте правило в его основном файле, а не копируйте в инструкции для разных CLI. Если изменение затрагивает границу слоёв или процедуру проверки, обновите документацию в том же PR. Локальная память агента — подсказка, а не источник актуальных путей, команд или решений.

## Как подключить разные CLI

| CLI | Что делать | Как проверить |
| --- | --- | --- |
| [Codex](https://developers.openai.com/codex/guides/agents-md/) | Читает `AGENTS.md`. Проверьте, нет ли `AGENTS.override.md` в том же каталоге: Codex выбирает его вместо основного файла. | Начните новую сессию из корня и попросите назвать загруженные правила. |
| [Claude Code](https://code.claude.com/docs/en/memory#agents-md) | Начиная с 2.1.277 читает `AGENTS.md` напрямую, если нет перекрывающего `CLAUDE.md` или `CLAUDE.local.md`. Если прямое чтение недоступно, в корневом `CLAUDE.md` достаточно строки `@AGENTS.md`; копировать правила не нужно. | `/context all` → **Memory files**. |
| [GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/add-repository-instructions) | Читает `AGENTS.md`. Отдельный `.github/copilot-instructions.md` не нужен, пока нет правил именно для Copilot. | `/instructions`, затем проверить, что `AGENTS.md` включён. |
| [Gemini CLI](https://geminicli.com/docs/cli/gemini-md/) | По умолчанию читает `GEMINI.md`; можно добавить `AGENTS.md` в `context.fileName` в настройках CLI или подключить его строкой `@./AGENTS.md` из корневого `GEMINI.md`. | `/memory show`; после правки `/memory reload`. |

Файлы совместимости, профильные инструкции и `SKILL.md` добавляйте только для реально используемого CLI и повторяющейся задачи. Например, если появится отдельная многошаговая процедура с проверкой, опишите её на одной странице и подключайте по необходимости, а не загружайте во все сессии.

## После смены или обновления CLI

1. Сверьте версию CLI и правила загрузки инструкций по его документации. Начните чистую сессию из корня; после изменения инструкций перезапустите сессию или используйте команду перезагрузки контекста, если она есть.
2. Проверьте загруженный файл средствами CLI. Затем без правок спросите: «Где добавить новый источник? Почему плеер не импортирует адаптер? Какой командой проверяем проект перед PR?» Сверьте ответы с `AGENTS.md` и `CONTRIBUTING.md`.
3. Если файл не загрузился, исправьте настройку обнаружения или добавьте короткую ссылку для этого CLI. Не создавайте вторую копию правил и не расширяйте права ради загрузки контекста.

Markdown помогает агенту выбрать действие, но не ограничивает его права. Обязательные проверки и запрет прямого пуша обеспечиваются настройками CLI и GitHub (изоляцией, подтверждением действий, защитой `main` и обязательным `verify`), а не одним текстовым файлом.
